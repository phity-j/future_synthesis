### 概要

AIは人間を完全には理解できない、という前提に立つと、AI安全の設計は変わります。この記事では、「理解が進む」「予測だけ進む」「限界を設計に組み込む」の3シナリオを比較し、業務でAIを使う際の判断基準とよくある質問に答えます。

### 結論

AIが人間を「理解できるか」を問うより、「理解しきれないとき、どう振る舞わせるか」を設計するほうが、安全に近づきます。

### AIが人間を理解するとは、どういうことか

AIにおける「理解」は、大量のデータからパターンを抽出し、人間の判断や反応を推測することです。人間の判断の多くは、経験や身体感覚など、言葉にならない要素を含みます。そのため、データ化できる部分だけを学ぶAIには、取りこぼしが生じます。

キーワードの整理です。


| 用語 | 意味 |
| ------------- | ---------------------------- |
| 抽象化 | 個々の違いを削って、共通パターンにまとめること |
| 暗黙知 | 言葉にしにくいが、確かに働いている知識（熟練者の勘など） |
| 自動化バイアス | 人が自動システムの出力を、そのまま信じやすくなる傾向 |
| キャリブレーション（校正） | AIの確信度と、実際の的中率が合っているかの度合い |


### 3つのシナリオで比較する

今後のAIと人間の関係を、3つのシナリオで整理します。


| シナリオ | 想定 | 起きやすいこと | リスク |
| ------------- | ------------------------------- | ------------------ | ------------------------ |
| A：理解が深まる型 | AIが人間を十分に理解できると仮定し、価値観を教え込む | 理解の精度は上がる | 少数派や例外が落ち、「理解したつもり」で暴走する |
| B：予測だけが進む型 | 行動の予測精度は高まるが、理由や感じ方は分からない | 予測の的中で信頼が高まる | 予測と理解を混同し、判断の責任が曖昧になる |
| C：限界を設計に組み込む型 | 理解できない前提で、不確実性の保持と人間への差し戻しを設計する | 重大な判断は人に戻り、例外が守られる | 止めすぎると、運用が滞る |


現実には、AとBの要素は今後も強まるでしょう。だからこそ、Cの設計を並行して整えておく価値があります。

### Cの型を支える5つの原則


| 原則 | 設計のポイント |
| ------------- | ----------------------- |
| 不確実性を持たせる | 意図の推測を、確定ではなく可能性として扱う |
| 分からないときは人間に戻す | 重大な判断は、確信がなければ自動で進めない |
| 平均値だけで判断しない | データが少ないケースを、重要でないと見なさない |
| 異議申し立てを残す | 人間が覆せる仕組みを用意する |
| 異なる人間が検証する | AI同士の相互チェックだけに頼らない |


構造設計の考え方に置き換えると分かりやすくなります。建物は、想定外の力が来る前提で余裕（安全率）を持たせます。AIにも、理解の限界を前提にした余裕が必要です。

### 業務での判断基準

AIを仕事に取り入れる際は、任せる範囲を事前に決めておきます。


| 判断項目 | 問い |
| ----- | -------------------- |
| 取り返し | 間違えたとき、修正できるか |
| 人への影響 | 相手の事情や感情が、大きく関わるか |
| データの量 | 前例や参考データは、十分にあるか |
| 覆せるか | AIの出力を、人が変更できる手順があるか |


### よくある質問

AIは人間を理解できますか。  
人間の行動を高い精度で予測することは、進んでいくでしょう。ただ、本人がなぜそう選び、どう感じているかまで含めた理解は、完全にはできません。

AIに「分からない」と言わせる意味は何ですか。  
重大な判断で、AIの推測が外れたまま進むのを防ぐためです。「分からない」を停止の合図として使います。

「最終承認は人間」だけで十分ですか。  
不十分な場合があります。人は、AIの答えを追認しがちです（自動化バイアス）。人間が覆せる手順と、その判断の記録を残すことが大切です。

少数派のケースが重視されるのはなぜですか。  
データが少ない状況は、AIが最も間違えやすいためです。「データが少ない＝重要ではない」とは言えません。

業務では何から始めればよいですか。  
まず、AIに任せる仕事と、人が判断する仕事を分けてください。次に、AIの出力を人が覆せる手順を決めます。

### まとめ

- AIは人間を完全には理解できない、という前提を置く
- 理解の限界を、設計とルールに組み込む
- 業務では、任せる範囲を事前に決める
